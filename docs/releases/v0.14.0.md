# Release v0.14.0

v0.14 unifies awman's long-running work behind one daemon and brings its engine to the browser, work servers, and the TUI. It also changes several commands and checkout paths; review **Upgrade notes** before updating scripts or resuming older worktrees.

## Features

- **One daemon for shared work.** `awman daemon start|stop|status|logs` manages the engine, worker, and squad features. The TUI can use the daemon's engine so sessions continue through a frontend disconnect and can be observed by other authorized frontends. Feature switches apply while the daemon is running.
- **Browser workspace.** The web app at [awman.prettysmart.dev](https://awman.prettysmart.dev) shows local workspaces, agent terminals, squad tasks, and the work queue. Enable the engine and loopback listener, register a workspace, and approve the browser with `awman link web-<code>`. The browser and daemon must be on the same computer; browser access is scoped to approved local workspaces.
- **Push and pull workers.** The worker API accepts remote sessions and commands. `awman link <server-url>` connects this machine to a work server, and `awman queue` / `awman queue pick` let you inspect and claim offered work. Automatic claims and manual picks share daemon capacity, with per-server limits and labels.
- **Agent-assisted creation and editing.** `awman new` and `awman edit` can author or revise specs, workflows, skills, and agent definitions. `awman edit spec <ref> --amend` reconciles a work item with evidence. Headless and JSON authoring are available for automation.
- **Linux x86_64 builtin runtime.** The experimental builtin microVM runtime now supports Linux x86_64 GNU with KVM, in addition to Apple Silicon macOS. The release binary carries the VM components; images still come from an explicit configured source.

## Improvements

- **Earlier, consistent setup checks.** Workflow, squad, and worker preparation review required images, Git identity, credentials, and overlays before running work. A compatible local image builder can rebuild missing or stale project and agent images; content identity lets unchanged images be reused.
- **Safer remote work.** Read-only remote workspaces, per-item secret injection, reviewed overlays, and prerequisite choices apply to worker leases. Git transport shares one credential path, including push retries and private ephemeral credentials.
- **More useful supervision.** Agent status appears in tabs and container windows; terminal sessions and workflow state remain available to the engine after a frontend disconnect. The web app reconnects to authorized local workspaces after a reload.
- **Agent choices.** Builtin support includes OpenCode 1.x, OpenCode 2.x, and Cursor. User-selected agent binary versions are allowed; OpenCode adapters check only the relevant major version.

## Fixes

- Preserved agent turn output when an ACP prompt completed, and improved terminal reconnect behavior.
- Improved builtin image-source setup and `ready` errors, including clearer build and import progress.
- Fixed workflow setup and checkout naming inconsistencies that could make resume behavior depend on an older path spelling.

## Upgrade notes

- The former `awman api start|stop|status` and `awman squad start|stop|logs` lifecycle commands are removed. Enable the relevant daemon feature and use `awman daemon start|stop|status|logs` instead. `awman squad` still manages your group of agents and its tasks.
- `awman specs amend` is removed. Use `awman edit spec <ref> --amend`.
- `--issue` is removed. Use `--work-item github:84` for a GitHub issue, or configure `workItems.source` for bare numbers. Missing or inaccessible work items now fail instead of silently continuing.
- Generated worktree, workflow, GitHub-issue, and remote-clone paths use one canonical naming policy. Old unhashed worktree directories and old branch spellings are no longer discovered automatically. awman does not migrate or delete them. Preserve outstanding changes with Git before recreating one.

For setup and exact commands, see [The daemon](../16-daemon.md), [Web App](../20-webapp.md), [Workers and work servers](../17-workers-and-work-servers.md), and the [command reference](../14-command-reference.md).
