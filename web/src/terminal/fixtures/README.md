# Terminal renderer fixtures and selection

These fixtures are awman.terminal.v1 frames (`snapshot` / `output` / `resize`,
base64 bytes) as the daemon's TerminalHub sends them. They were produced by
`generator/main.rs.txt` (a standalone Cargo program, manifest in
`generator/Cargo.toml.txt`) with **vt100-ctt 0.17.1**, the parser behind the
hub's `ScreenMirror`: every `snapshot.screen` is `Screen::state_formatted()`,
exactly what the hub sends on connect, lag and reconnect. Each file records the
hub's final screen (`expect`) and what a fresh parser shows from the final
snapshot alone (`expect_from_snapshot`). `test/terminal/fixtures.test.ts`
replays every fixture both ways through the real adapter and compares the
rendered DOM text, cursor and modes.

| Fixture | Covers |
|---|---|
| `utf8_split` | UTF-8 split across frames at every byte (1- and 3-byte chunks) |
| `wide_graphemes` | CJK, fullwidth, combining marks, wide char at the wrap edge, split frames |
| `emoji_sequences` | Emoji modifiers, flags, ZWJ (known width divergence, below) |
| `alt_screen_redraw` / `alt_screen_exit` | Agent-TUI redraw loop on 1049 with 2026 synchronized output, CUP/EL, 256/true colour; leaving the alt screen |
| `colours` | 16/256/true colour fg/bg, bold, dim, italic, underline, inverse, strike |
| `cursor_modes` | CUP, DECSC/DECRC, hidden cursor, DECCKM |
| `mouse_sgr` / `mouse_any_x10enc` | 1000/1002/1003 tracking with SGR (1006) and default encoding |
| `bracketed_paste` | 2004 |
| `resize_storm` | 8 resize frames with redraws, a mid-stream snapshot, more output |
| `scrollback_10k` | 10 000 lines (output regenerated by the test; see `numberedLinesFrames`) |
| `untrusted_osc` | OSC 0/2 titles with markup, OSC 8 (https + javascript:), OSC 52/7/9/777/1337, DCS/XTGETTCAP, Kitty APC, Sixel |

## Comparison (wterm 0.5.10)

| | wterm built-in core (`@wterm/core`, Zig WASM, 53 KB) | wterm Ghostty core (`@wterm/ghostty`, libghostty-vt WASM, 586 KB / 194 KB gz) |
|---|---|---|
| UTF-8 split, wide graphemes, alt-screen, colours, cursor, modes, resize storm, 10k scrollback | pass | pass |
| `untrusted_osc` | **fail**: DCS/PM/SOS payloads (XTGETTCAP, Sixel, `ESC ^`, `ESC X`) are printed as visible text | pass (all strings consumed) |
| Scrollback bound in lines | yes | yes (0.5.5 ignored `scrollbackLines`; fixed by 0.5.10) |
| Emoji modifier/flag/ZWJ widths | grapheme clusters (width 2) | grapheme clusters (width 2) |

Both cores differ from the hub's vt100-ctt on `emoji_sequences`: vt100 sizes
each code point, wterm sizes grapheme clusters (as agent TUIs built on
`string-width` do). The test asserts the clusters stay intact rather than
exact columns.

`@wterm/dom` / `@wterm/react` were evaluated and **not used**: the DOM renderer
builds rows with `innerHTML` carrying `style="…"` attributes (blocked by the
production CSP `style-src 'self'`, so colours vanish and every repaint raises
violations) and renders OSC 8 cells as `<a href target=_blank>`. awman uses the
headless core plus its own renderer (`adapter/renderer.ts`: `textContent`,
class names, CSSOM colours, no anchors).

**Decision:** `@wterm/ghostty` + `@wterm/core`, pinned to exactly **0.5.10**.

## WASM and CSP

Both wterm cores are WebAssembly, so `script-src` needs `'wasm-unsafe-eval'`
(never `'unsafe-eval'`). Verified in headless Chromium with the edge CSP:
without it compilation is refused (`script-src wasm-eval` violation; the view
shows "The terminal renderer could not be loaded."); with it the core loads,
CSSOM colours apply and there are no violations. The `.wasm` is emitted
self-hosted as `/_next/static/media/ghostty-vt.<hash>.wasm`, listed by
`audit-csp`, and precached by the service worker.

## Regenerating

```
cp generator/Cargo.toml.txt /tmp/fixgen/Cargo.toml
cp generator/main.rs.txt /tmp/fixgen/src/main.rs
cd /tmp/fixgen && cargo run -- <this directory>
```
